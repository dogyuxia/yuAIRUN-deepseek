## 1. 需求背景与目标

### 1.1 为什么要引入用户系统

当前 MVP 核心功能（输入→AI出题→答题→报告→分享）已开发完成，但存在以下问题：

| 问题 | 说明 |
|------|------|
| ❌ **用户身份缺失** | 无法区分不同用户，所有数据仅存本地，换设备即丢失 |
| ❌ **数据无云端备份** | 本地存储容量有限（最多 50 条历史、100 道错题），且清除缓存即丢失 |
| ❌ **无法跨设备同步** | 用户不能在多个设备上共享学习进度 |
| ❌ **无社交分享基础** | 微信生态的核心优势（好友分享、排行）无法发挥 |
| ❌ **无用户画像** | 无法分析用户的学习行为和偏好，无法个性化推荐 |

### 1.2 本次需求的目标

1. **建立完整的用户身份体系**：基于微信授权登录，实现用户注册、登录、身份识别
2. **实现用户数据的云端持久化**：答题历史、错题本、学习统计数据存储到服务端
3. **开发个人中心**：用户查看自己的学习概况、统计数据、管理错题本
4. **为后续功能奠定基础**：排行榜、PK对战、VIP充值等功能的用户体系基础

## 3. 【P0】用户登录认证 — 需求详情

### 3.1 概述

> **核心目标**：用户打开小程序即自动完成身份识别，无需手动注册，零摩擦体验。
> **设计原则**：借鉴微信生态「用完即走」理念，登录流程应在 1 秒内无感完成。

### 3.2 业务流程

```
用户打开小程序
       │
       ▼
  ┌─────────────────────┐
  │ 检查本地 Token      │
  │ (wx.getStorageSync) │
  └─────────┬───────────┘
            │
     ┌──────┴──────┐
     ▼              ▼
  有 Token        无 Token
     │              │
     ▼              ▼
  ┌──────────┐  ┌──────────────────────┐
  │验证 Token │  │ 调用 wx.login()      │
  │是否过期   │  │ 获取临时 code        │
  └────┬─────┘  └──────────┬───────────┘
       │                   │
  ┌────┴─────┐            ▼
  │          │     ┌──────────────────────┐
  ▼          ▼     │ POST /api/user/login │
有效       过期   │ (code → openid)      │
  │          │     │ → 注册/登录          │
  │          │     │ → 返回 JWT Token    │
  │          │     └──────────┬───────────┘
  │          │                │
  │          └──────┬─────────┘
  │                 ▼
  ▼        ┌──────────────────────┐
 进入首页   │ 保存 Token 到本地    │
           │ 缓存用户基本信息     │
           └──────────┬───────────┘
                      ▼
                  进入首页
```

### 3.3 接口设计

#### `POST /api/user/login` — 微信登录

| 项目 | 说明 |
|------|------|
| **功能** | 使用微信临时 code 登录/注册，返回 JWT Token |
| **是否需要认证** | ❌ 否（公开接口） |

**请求体：**
```json
{
  "code": "微信临时登录凭证",
  "nickname": "微信昵称（可选，首次登录时使用）",
  "avatarUrl": "微信头像 URL（可选，首次登录时使用）"
}
```

**成功响应：**
```json
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "expiresIn": 2592000,
    "user": {
      "id": "u_abc123",
      "nickname": "小明",
      "avatarUrl": "https://thirdwx.qlogo.cn/...",
      "xp": 0,
      "level": 1,
      "isNewUser": true
    }
  }
}
```

**错误响应：**
```json
{
  "success": false,
  "error": "登录失败，请重试"
}
```

#### `POST /api/user/refresh-token` — 刷新 Token

| 项目 | 说明 |
|------|------|
| **功能** | 使用旧 Token 换取新 Token |
| **是否需要认证** | ✅ 是 |

**请求体：**
```json
{
  "token": "旧 JWT Token"
}
```

**成功响应：**
```json
{
  "success": true,
  "data": {
    "token": "新 JWT Token",
    "expiresIn": 2592000
  }
}
```

### 3.4 数据结构

#### 用户表 (User)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 用户唯一 ID（自动生成，如 `u_xxx`） |
| `openid` | string | 微信 openid（唯一标识） |
| `unionid` | string? | 微信 unionid（如有） |
| `nickname` | string | 微信昵称 |
| `avatarUrl` | string | 微信头像 URL |
| `xp` | integer | 经验值 |
| `level` | integer | 等级（由 XP 计算） |
| `lastLoginAt` | datetime | 最后登录时间 |
| `createdAt` | datetime | 首次注册时间 |
| `updatedAt` | datetime | 信息更新时间 |

#### 等级经验值对照表

| 等级 | 所需 XP | 称号 |
|:----:|:-------:|------|
| 1 | 0 | 🧑‍🎓 初学者 |
| 2 | 100 | 📚 学徒 |
| 3 | 300 | 🔍 探究者 |
| 4 | 600 | 🧠 学者 |
| 5 | 1000 | 🏆 大师 |
| 6 | 2000 | 👑 传奇 |

> XP 获取规则：答对一题 +10 XP，连续答题额外奖励 +5 XP/题。

### 3.5 前端交互说明

1. **自动静默登录**：小程序启动时，自动用本地缓存的 Token 尝试登录
   - Token 有效 → 直接进入首页
   - Token 过期 → 自动刷新 Token
   - 刷新失败 → 重新调用 `wx.login()`
2. **首次登录**：显示「正在登录...」的轻提示，无需用户点击任何按钮
3. **登录失败**：不影响核心功能，用户仍可使用本地模式，数据暂存本地
4. **微信头像加载**：使用 Taro 的 `Image` 组件加载微信头像，默认圆角显示

### 5.3 前端交互说明

1. **闯关历史**：答题完成后自动同步到服务端，无需用户手动操作
2. **错题本同步**：
   - 每道题答错后自动记录到本地错题本
   - 用户登录后，自动将本地错题同步到服务端（增量同步）
   - 支持"重新练习"：将错题重新组装为一次闯关
   - 支持"标记已掌握"：从错题本移除
3. **数据同步策略**：
   - 先写本地，再同步服务端（离线可用）
   - 同步失败不阻塞用户操作，后台重试
   - 同步冲突时以服务端数据为准

## 7. 数据同步策略

### 7.1 整体策略

```
用户操作
    │
    ▼
┌──────────────┐    成功     ┌──────────────────┐
│  本地存储      │ ────────▶ │  MySQL 数据库     │
│  (Zustand +   │            │  (SQLAlchemy ORM) │
│   Storage)    │ ◀────────  │                   │
└──────────────┘   失败     └──────────────────┘
       │                        │
       ▼                        ▼
  下次打开小程序           结构化关系存储
  时后台重试                支持复杂查询

### 7.2 具体规则

| 数据类型 | 写入策略 | 读取策略 | 冲突处理 |
|---------|---------|---------|---------|
| 用户信息 | 同步写入 | 优先服务端 | 服务端为准 |
| 闯关历史 | 先写本地，后同步 | 优先服务端（分页） | 服务端为准 |
| 错题本 | 先写本地，后同步 | 合并本地+服务端 | 保留较新版本 |
| XP/等级 | 服务端计算 | 服务端 | 服务端为准 |

## 8. 非功能性需求

### 8.1 性能要求

| 接口 | 预期耗时 | 超时阈值 |
|------|---------|---------|
| `POST /api/user/login` | < 500ms | 5s |
| `GET /api/user/profile` | < 200ms | 5s |
| `GET /api/user/history` | < 300ms | 10s |
| `GET /api/user/wrong-book` | < 300ms | 10s |
| `POST /api/user/history/sync` | < 1s | 15s |

### 8.2 安全要求

1. **Token 安全**：
   - JWT Token 有效期 30 天
   - Token 存储于本地 Storage，不在 URL 中传递
   - 使用 Bearer Token 方式在 Header 中传递
2. **数据隐私**：
   - 用户数据仅本人可访问
   - 不存储用户明文密码
   - 不使用微信敏感信息（如手机号）
3. **接口防护**：
   - 登录接口做频率限制（同 IP 每分钟最多 10 次）
   - 需认证的接口统一验证 Token

### 8.3 兼容性要求

1. **降级策略**：
   - 服务端不可用时，用户仍可使用本地模式
   - 登录失败不影响本地数据的使用
   - 数据在本地缓存，待网络恢复后自动同步
2. **微信版本兼容**：
   - 支持基础库版本 >= 2.14.1
   - 适配不同屏幕尺寸的微信小程序
