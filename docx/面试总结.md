# yuAIRUN — 面试项目总结（AI Agent 方向）

## 1. 核心难点与解决

**难点：基于 RAG 的知识库出题链路不通**

项目引入了本地知识库（RAG），但用户始终无法从知识库中匹配到内容出题，表现为三个连锁问题：

| 问题 | 根因 | 解决 |
|:----|------|------|
| **Embedding 模型加载阻塞** | 子进程验证模型导致同步阻塞 300s，且 HuggingFace `.no_exist` 缓存标记导致模型被误判为损坏 | 移除子进程验证，改用直接加载 + 文件缓存检测；清理 `.no_exist` 残留 |
| **模型路径解析错误** | 相对路径 `./models_cache` 相对于 CWD 解析，而 uvicorn 启动目录不在 backend 下 | 在 `Settings.__init__` 中将所有相对路径基于 `BACKEND_DIR` 转为绝对路径 |
| **LangChain ChatPromptTemplate 模板变量冲突** | 知识库文档中的代码示例含 `{}`（如 JSON、函数定义），`ChatPromptTemplate.from_messages` 误解析为模板变量 | 改用 `llm.ainvoke(full_prompt)` 直接传字符串，绕开模板引擎 |

> 此外修复了 12 个业务 Bug（登录依赖注入、知识库 CRUD 响应格式、新建按钮被遮挡、报告重刷不刷新等）

## 2. AI Agent 相关思路

### RAG 知识库架构

```
用户输入 Topic
     │
     ▼
┌─────────────────────────────┐
│    出题模式选择               │
│ ① AI 搜索（Tavily Agent）    │ ← AI Agent 自主搜索策略
│ ② 仅知识库（ChromaDB RAG）    │ ← 向量检索 + 上下文注入
│ ③ 混合模式                   │ ← Agent + RAG 融合
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│   DeepSeek + with_structured│
│   _output 统一出题          │
└─────────────────────────────┘
```

**关键设计点：**

- **三种模式并行 + 用户可选**：搜索增强（Tavily Agent）、知识库（ChromaDB RAG）、混合模式。为后续 **Agentic RAG**（AI 自主判断检索方式）打下架构基础
- **BGE-M3 (1024维) + ChromaDB**：中英双语的本地 Embedding 模型，平衡精度与部署成本；ChromaDB PersistentClient 零运维
- **系统内置 20 篇知识文档**：覆盖 AI Agent 基础概念、LangChain 框架、ReAct 模式、Prompt Engineering、RAG 技术等，冷启动即有内容
- **文档处理流水线**：TXT/MD → Docling 解析 → RecursiveCharacterTextSplitter 分块 → BGE-M3 向量化 → ChromaDB 索引，全异步非阻塞

**Agent 相关性：** 项目涉及 LLM 工具调用（Tavily Search/Extract）、Agent 自主搜索策略、RAG 检索增强生成、向量语义检索等 AI Agent 核心技术栈。
