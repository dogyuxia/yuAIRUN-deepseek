# 计算机基础面试题

## 1. TCP 三次握手与四次挥手

**三次握手（建立连接）：**
1. 客户端 → SYN → 服务端（客户端进入 SYN_SENT）
2. 服务端 → SYN+ACK → 客户端（服务端进入 SYN_RCVD）
3. 客户端 → ACK → 服务端（双方进入 ESTABLISHED）

**四次挥手（断开连接）：**
1. 客户端 → FIN → 服务端（客户端进入 FIN_WAIT_1）
2. 服务端 → ACK → 客户端（服务端进入 CLOSE_WAIT）
3. 服务端 → FIN → 客户端（服务端进入 LAST_ACK）
4. 客户端 → ACK → 服务端（客户端进入 TIME_WAIT）

## 2. HTTP 与 HTTPS 区别

| 特性 | HTTP | HTTPS |
|:----|:----:|:-----:|
| 加密 | 明文传输 | SSL/TLS 加密 |
| 端口 | 80 | 443 |
| 证书 | 不需要 | 需要 CA 证书 |
| 安全 | 易被窃听篡改 | 防窃听防篡改 |

## 3. RESTful API 设计原则

- 使用名词而非动词：`GET /users` 而非 `GET /getUsers`
- 利用 HTTP 方法：GET（查）、POST（增）、PUT（改）、DELETE（删）
- 状态码语义化：200（成功）、201（创建）、400（参数错误）、401（未认证）、404（不存在）、500（服务端错误）
- 无状态：每次请求包含所有必要信息

## 4. MySQL 索引原理

**B+树索引特点：**
- 非叶子节点只存索引值，不存数据
- 叶子节点存数据且形成有序链表
- 树高一般为 2~4 层，查询效率稳定
- 支持范围查询（叶子节点链表直接遍历）

**索引优化建议：**
- 联合索引遵循最左前缀原则
- 不要对区分度低的列建索引（如性别）
- 索引不是越多越好，影响写性能
- 用 EXPLAIN 分析执行计划

## 5. Redis 数据结构与应用

| 结构 | 底层实现 | 典型场景 |
|:----|:--------:|---------|
| String | SDS | 缓存、计数器、分布式锁 |
| Hash | dict+ziplist | 对象存储 |
| List | quicklist | 消息队列、最新列表 |
| Set | intset+hashtable | 标签、去重 |
| ZSet | skiplist+dict | 排行榜、延时队列 |
