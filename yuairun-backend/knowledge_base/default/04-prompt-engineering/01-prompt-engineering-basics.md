# Prompt Engineering 基础

## 什么是 Prompt Engineering？

Prompt Engineering（提示工程）是**设计和优化输入给 LLM 的指令**，以获得更准确、更有用的输出。它是 AI 应用开发中最基础也最重要的技能之一。

## 好 Prompt 的五个要素

### 1. 角色设定 (Role)

给 LLM 一个明确的角色，帮助它理解回答问题的角度和风格。

```
❌ "生成一些题目"
✅ "你是一位经验丰富的学科专家，擅长根据学习内容生成高质量的练习题"
```

### 2. 任务描述 (Task)

清晰说明 LLM 需要完成的具体任务。

```
❌ "帮我出题"
✅ "请根据以下学习内容，生成 5 道单选题，每道题包含选项、正确答案和详细解析"
```

### 3. 上下文 (Context)

提供足够的背景信息，帮助 LLM 理解场景。

```
✅ "你正在为一门大学课程设计期中考试题目，学生已经学习了 TCP/IP 协议栈的基础知识"
```

### 4. 格式要求 (Format)

明确指定输出的格式、结构和约束。

```
✅ "按 JSON 格式输出，使用以下结构：{questions: [{question, options: [{label, content}], answer, explanation}]}"
```

### 5. 示例 (Examples)

提供输入输出的示例，帮助 LLM 理解期望。

```
✅ "例如：
输入：'TCP 三次握手'
输出：{
  question: 'TCP 建立连接时，客户端发送的第一个报文段的SYN标志位是？',
  options: [
    {label: 'A', content: 'SYN=0'},
    {label: 'B', content: 'SYN=1'}
  ],
  answer: 'B',
  explanation: 'TCP三次握手中...'
}"
```

## Prompt 结构化模板

### System Prompt（系统提示）

定义 AI 的行为准则和角色：

```python
SYSTEM_PROMPT = """你是一位专业的出题专家，擅长根据学习内容生成高质量的练习题。

## 核心原则
1. 题目必须准确、专业、无歧义
2. 选项必须合理，干扰项要有迷惑性但不能误导
3. 解析必须详细、清晰，帮助学生理解知识点
4. 难度分布要合理

## 难度定义
- easy（简单）：考查基础概念和定义的记忆
- medium（中等）：考查概念的理解和简单应用
- hard（困难）：考查综合分析、比较和实际应用

## 输出格式
严格按照 JSON 格式输出..."""
```

### Human Prompt（人类提示）

包含用户的具体输入和参数：

```python
HUMAN_PROMPT = """请根据以下学习内容，生成 {count} 道题目。

## 学科：{subject}
## 知识点：{topic}
## 题目配置
- 数量：{count}
- 难度：{difficulty}
- 类型：{type}"""
```

## 常见的 Prompt 技巧

### 1. 链式思考 (Chain-of-Thought)

引导 LLM 逐步推理，而不是直接给出答案：

```
❌ "判断以下代码是否有 bug"
✅ "请逐步分析以下代码的执行流程：
    1. 先分析输入参数
    2. 再分析函数内部的逻辑
    3. 检查边界条件
    4. 最后判断是否存在 bug"
```

### 2. 负向提示 (Negative Prompt)

告诉 LLM 不要做什么：

```
✅ "不要编造参考资料中没有的信息"
✅ "不要使用过于学术化的语言"
✅ "不要生成含有争议或敏感内容的题目"
```

### 3. 温度控制 (Temperature)

| Temperature | 效果 | 适用场景 |
|:-----------:|------|---------|
| 0.0~0.3 | 确定性高，重复性好 | 事实问答、代码生成 |
| 0.4~0.7 | 平衡创造力和准确性 | 题目生成、内容创作 |
| 0.8~1.0 | 创造力强，多样性高 | 创意写作、头脑风暴 |

### 4. Few-shot（少样本学习）

提供少量示例比纯描述更有效：

```
✅ 为每种题型提供一个示例：
单选示例：...
多选示例：...
判断示例：...
```

### 5. 约束条件 (Constraints)

明确限制输出的范围：

```
✅ "必须基于以下参考资料出题"
✅ "每道题不超过 200 字"
✅ "题目难度必须覆盖简单、中等、困难各至少 1 题"
```

## Prompt 迭代优化流程

```
初始 Prompt
    │
    ▼
测试 → 效果不好 → 分析问题 → 修改 Prompt → 再测试
    │
    ▼
效果达标 → 锁定版本
```

### 常见问题与对策

| 问题 | 对策 |
|------|------|
| 输出格式不稳定 | 使用 with_structured_output 绑定 Pydantic 模型 |
| 内容不准确 | 增加参考资料/上下文约束 |
| 重复性高 | 提高 temperature，增加变化性提示 |
| 漏掉要求 | 用 Markdown 标题分层，关键要求加粗 |
| 太啰嗦 | 增加字数限制，要求精炼 |

## 本项目中的 Prompt 设计

在 yuAIRUN 中，Prompt 被设计为分层结构：

```
System Prompt（系统层）
├── 角色定义：出题专家
├── 核心原则：准确性、专业性
├── 难度定义：easy/medium/hard
└── 输出格式：JSON schema

Human Prompt（用户层）
├── 学科和知识点
├── 题目配置（数量/难度/类型）
└── 参考资料（搜索增强/RAG 上下文）
```
